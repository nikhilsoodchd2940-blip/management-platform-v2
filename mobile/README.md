# Mobile — Flutter (Member + Host)

One codebase for both Member and Host experiences (blueprint §2), branching on the role custom claim after login.

## Structure

```
lib/
  main.dart              App entry, Firebase + Stripe init
  core/                  Firebase config (generated, gitignored), session state, routing, offline check-in queue
  features/
    auth/                OTP login
    profile/             View/edit own profile, notification preference, donate, sign out
    groups/              Member's Sub Groups + group detail (chat, propose event)
    events/              Member's events + conflict warnings + request absence
    qr/                  Personal QR display
    notifications/       Inbox shell
    absence/             Request-absence dialog
    requests/            Propose-event form
    chat/                Group chat screen with image attachments (shared by Member + Host)
    donations/           Donation screen (Stripe Payment Sheet)
    host/                Host's assigned groups, member lists, event list, QR scan (with offline queue + sync), absence review
  shared/                Shared widgets/models used across features
```

## Before this runs

1. `flutterfire configure` — generates `lib/core/firebase_options.dart` for each environment flavor (dev/staging/prod). Not committed with real values.
2. `flutter pub get`.
3. Google Maps API key wired into `android/app/src/main/AndroidManifest.xml` and `ios/Runner/AppDelegate.swift` per platform (restricted key, see `docs/INTEGRATIONS.md`).
4. **Phase 2 (camera + location permissions)** — required for the Host QR-scanning flow (`features/host/qr_scan_screen.dart`) and reported honestly: not yet added anywhere, since `android/`/`ios/` don't exist in this repo yet (generated by `flutter create .`, run in your own environment). Once generated, add:
   - **Android** (`android/app/src/main/AndroidManifest.xml`): `<uses-permission android:name="android.permission.CAMERA" />` and `<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />`.
   - **iOS** (`ios/Runner/Info.plist`): `NSCameraUsageDescription` ("Used to scan attendee QR codes") and `NSLocationWhenInUseUsageDescription` ("Used to confirm you're at the event location during check-in").
5. **Phase 3 (Stripe donations)** — pass the publishable key at build/run time rather than hard-coding it:
   ```bash
   flutter run --dart-define=STRIPE_PUBLISHABLE_KEY=pk_test_...
   ```
   `flutter_stripe` also needs minimum platform versions once `android/`/`ios/` exist: Android `minSdkVersion 21` in `android/app/build.gradle`, iOS deployment target 13.0+ in `ios/Podfile`. See the package's own setup docs for specifics current at whatever `flutter_stripe` version `pubspec.yaml` resolves to.
6. **Phase 4 (chat media, photo library permission)** — `image_picker` needs one more permission entry once `android/`/`ios/` exist:
   - **Android**: no extra manifest entry needed for gallery picks on modern Android (scoped storage) — only the Phase 2 entries above are required.
   - **iOS** (`ios/Runner/Info.plist`): `NSPhotoLibraryUsageDescription` ("Used to attach photos to group chat messages").
7. **Phase 4 (offline QR queue)** — `connectivity_plus` and `shared_preferences` need no extra native permissions beyond what's already listed above; both work out of the box once the platform folders exist.

Standard `android/`, `ios/` platform folders are generated by `flutter create .` in your own environment (this sandbox has no Flutter SDK/network) — do that once, then this `lib/` tree drops in.
